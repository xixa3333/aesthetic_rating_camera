# 📸 智慧終端即時構圖評分系統 (Smart Camera AI)

**「讓每一次快門，都精準捕捉美學極致」** —— 基於 Flutter 與 TensorFlow Lite 邊緣運算之即時美學構圖評分系統。

---

## 👥 一、專題團隊與附件資訊

* **交付源碼版本**：`v1.0.0-Release` (Build 202606)
* **附件應用程式**：`SmartCamera_v1.0_Release.apk`（可直接安裝於 Android 實體機測試）

---

## 💡 二、系統開發背景與動機

本專案旨在開發一款**「具備視覺審美判斷力的智慧相機」**。有別於傳統易受主觀情緒與比賽主題綁架的評分機制，本系統透過自訂 Huber 損失函數，成功過濾高達 1.98 分的物理底噪，將平均絕對誤差壓縮至 0.94 分，精準萃取純視覺的客觀構圖大眾共識。

透過將此輕量化 CNN 模型掛載於行動裝置端，系統能在拍攝者**移動鏡頭運鏡的過程中，提供即時、低延遲的「浮動美學構圖分數」**，協助拍攝者在完美構圖誕生的瞬間按下快門，大幅降低商業攝影的素材篩選成本。

## 🛠️ 三、系統核心規格與技術棧 (Tech Stack)

* **UI 渲染框架**: Flutter 3.x (開啟 Material Design 3 高視覺張力深色主題)
* **核心程式語言**: Dart 3.x (具備健全空安全 Null Safety)
* **邊緣推論引擎**: TensorFlow Lite C++ API 封裝 (`tflite_flutter` v0.10+)
* **美學評分大腦**: 輕量化卷積神經網絡模型 `mobilenet_512_simp_float16.tflite`
* **底層色彩解碼**: ITU-R BT.601 標準矩陣解碼演算法（純 Dart 實作）
* **目標運行環境**: Android 10 ~ 14+ (API Level 29 ~ 34)
* **硬體調用權限**: 硬體相機高速接力串流、系統公共相簿沙盒穿透寫入權

## 📂 四、系統模組解耦與源碼導覽 (Separation of Concerns)

本系統捨棄傳統單一 God File 寫法，採用嚴謹的 **微型 MVC 架構** 進行職責切離：

```text
lib/
 ├── main.dart             ➔ [Entry / Config] 系統生命週期入口與全域硬體參數盤點
 ├── camera_screen.dart    ➔ [View / UI] 即時相機流渲染、動態手勢矩陣與測光管線
 └── ai_worker.dart        ➔ [Model / Engine] 高並發 Isolate 運算進程與推論數據管線

```

## 📱 五、前端架構與邊緣運算模組解析 (Edge AI Implementation)

為確保在資源受限的行動裝置上實現流暢的即時評分，本專案導入 Dart Isolate 進行非同步邊緣運算，核心架構由以下三個關鍵模組構成：

### 1. 系統進入點與全域組態 (`main.dart`)

做為應用程式的生命週期起點，負責系統層級的硬體資源初始化。

* **相機資源盤點**: 在 Flutter 引擎啟動前，非同步攔截並獲取設備的實體鏡頭清單 (`availableCameras`)，並將其註冊為全域變數 `globalCameras`，確保後續 UI 層能達成零延遲的鏡頭掛載。

### 2. 視圖與硬體控制層 (`camera_screen.dart`)

負責即時相機串流渲染、使用者硬體操作（變焦、曝光），以及推論任務的派發。

* **狀態管理**: 使用 `ValueNotifier` 實作極輕量級的局部狀態刷新（如分數與變焦），避免 `setState` 造成全域重繪，確保 UI 渲染維持 60 FPS 滿幀運行。
* **動態丟幀與背壓控制 (Backpressure)**: 實作生產者-消費者防禦機制。在相機流的回呼函數中，透過 `_isProcessing` 互斥鎖，主動丟棄在 AI 推論期間產生的多餘影格，徹底根絕 OOM (Out of Memory) 記憶體溢出危機。
* **跨執行緒通訊**: 負責建立與管理 `_backgroundIsolate`，並將攔截到的未編碼 `CameraImage` (YUV420 格式) 透過 `SendPort` 派發至背景進行運算。

### 3. 背景非同步推論引擎 (`ai_worker.dart`)

封裝 TensorFlow Lite C++ API 的高密碼運算進程，確保繁重的張量運算絕對不阻塞 Main UI Thread。

* **色彩空間解碼**: 將 Android/iOS 原生的 YUV420 串流資料，透過手動實作的轉換矩陣精準解碼為 RGB 色彩空間。
* **張量幾何對齊 (MeanPadToSquare)**: 針對手機端長寬比不固定的問題，嚴格重現 Python 訓練端的前處理邏輯。採用平均色塊填充法，將影像安全縮放至 512x512，嚴格防止視覺特徵在進入模型前遭到物理擠壓或扭曲。
* **推論與正規化**: 執行 `float16.tflite` 推論，並將模型輸出的絕對常規分數（基於 V 型權重拉伸的宇宙分數），逆向正規化至 0.0 ~ 1.0 的區間，回傳給 Main Thread 進行 UI 動態更新。
